Three facts that shape everything below
  1. turbo.json declares no test task, and neither @repo/shared nor @repo/email-renderer has a check-types script — the two packages holding the domain. Every drift below is invisible to the pipeline.
  2. Defaults are described twice — once as a zod schema, once as an untyped table — and the renderer describes them a third time as literals. Two have already diverged in ways that ship.
  3. The two biggest seams in the product (the iframe bridge, the web↔api envelope) are typed but not enforced: both have a live contract mismatch that compiles clean.

Top recommendation

C4 — Make the block definition table answer to its zod description preceded by C12, which is a ten-minute change

It is the smallest diff with the largest reach. TEMPLATE_BLOCK_DEFINITIONS is the data that the inspector, the palette, brand-kit resolution, createBlock, and every renderer read — and it is 476 untested lines typed as Record<string, unknown> sitting next to 329 untested lines of zod that describe the same thing. One table-driven test plus one type change closes three drift classes at once, deletes the digit-sniffing coercion downstream, and turns "add a Block type" from 13 files (8 of them silent) into something the compiler checks. C12 comes first only because without a test task, that test never runs.
